# CADD Applet for UKB-RAP

## Overview

This DNAnexus applet performs CADD (Combined Annotation Dependent Depletion) annotation on variant files. It processes multiple VCF files in parallel using Singularity containers and generates compressed TSV files with CADD scores for downstream analysis.

## Features

- Processes multiple input variant files in parallel.
- Supports various input formats: VCF, BCF, PVAR, TSV, and compressed variants (gz, zst, bgz).
- Uses Singularity/Apptainer containerization for reproducible CADD scoring.
- Logging and job summaries.
- Efficient parallel streaming of inputs and annotation resources from DNAnexus platform to reduce overhead to ~30 min.

## Input Specifications

### Required Inputs

- **cadd_input** (array:file): Array of variant file IDs
  - Supported formats: `.vcf`, `.vcf.gz`, `.vcf.bgz`, `.pvar`, `.pvar.zst`, `.pvar.zstd`, `.bcf`, `.tsv.gz`, `.tsv`

- **cadd_dir_path** (string): CADD data directory on DNAnexus RAP platform
  - Default: `/Resources/cadd_v1_7_data`.
  - Note: This contains an uncompressed version of the annotation resources tar, prescored variants, and two SIF images.

- **cadd_dir_project** (string): DNAnexus project containing the CADD data directory
  - Default: `project-GzKk3XjJZz4ZgXzP2v1029qB`


### Optional Inputs

- **cadd_jobs** (int): Number of files to process in parallel
  - Default: Auto-calculated based on available memory (1 job per 8GB RAM)

- **cadd_timeout** (int): Timeout per file in seconds
  - Default: 3600 (1h)

## Output Specifications

- **cadd_scores** (array:file): Compressed TSV files with CADD annotations
  - One `.cadd.tsv.gz` file per input VCF
  - Contains CADD scores and related annotations

- **cadd_logs** (array:file): Individual log files for each processed file
  - One `.cadd.log` file per input VCF
  - Contains stdout and stderr for each job

- **cadd_summary_log** (file): Overall job summary
  - Tabular summary of all CADD annotation jobs
  - Includes runtime, pass/fail status, and exit codes

## System Requirements

- **Instance Type**: defaults to `mem1_ssd1_v2_x36`
- **Distribution**: defaults to Ubuntu 24.04
- **Dependencies**:
  - Apptainer (Singularity) 1.4.1 (asset provided with the applet)
  - CADD v1.7 Singularity container and data files (downloaded from provided directories)

## How It Works

1. **Initialization**: Installs Apptainer and sets up working directories
2. **Input Preparation**: Downloads and preprocesses VCF files
   - Streams files from DNAnexus
   - Extracts first 5 columns (CHROM, POS, ID, REF, ALT)
   - Normalizes chromosome naming (removes "chr" prefix, converts "chrM" to "MT")
3. **Data Download**: Retrieves CADD reference data in parallel
4. **CADD Scoring**: Runs CADD annotation inside Singularity container
   - Uses GNU Parallel for efficient job distribution
   - Timeout: 3600 seconds per file (adjust in main entry point for large files)
5. **Results Collection**: Gathers output files and generates summary logs
6. **Upload**: Uploads all outputs back to DNAnexus

## Usage Example


To run on GUI, build from a cloned repository using DX client (e.g., via TTYD) then click the object 'ukb_cadd_applet' in your target build directory.


```bash
dx build --brief -d "project-id:DESIRED/DIR/PATH/" -f /PATH/TO/UKB_WGS_500k_RVAS/applets/cadd/
```


To run from CLI, build from this repository (cloned locally), then pass the input file IDs or full path.


```bash
ukb_cadd_applet_id=$(dx build --brief -d "project-id:DESIRED/DIR/PATH/" -f /PATH/TO/UKB_WGS_500k_RVAS/applets/cadd/ | jq -r .id)
```


```bash
dx run $ukb_cadd_applet_id \
  -icadd_input=file-xxx \
  -icadd_input=file-yyy \
  --destination "project-id:path/to/dir" \
  --brief
```

## Performance Notes

- If not indicated explicitly, parallel jobs are automatically determined based on available memory (1 job per 8GB)
- Uses optimized container approach: single container launch with parallel jobs inside
- Efficient streaming avoids unnecessary local storage of large VCF files
- Typical processing time varies by file size and variant count

# Annotating indels with CADD 1.7

CADD is rather slow (~7min per 5k VCF). A good strategy is to annotate indels only and use the output along with pre-scored SNVs as input to VEP. This gets all annotations in one place. It helps also if one uses 'no_anno' indels and removes the pre-scored SNVs from CADD data dir (reduces both the download and search time). 

## Creating input files

Start a VM with CWS or TTYD

```bash
dx run app-cloud_workstation \
--instance-type mem1_ssd1_v2_x2 \
--priority high \
--ssh \
--brief
```

Install bcftools

```bash
sudo apt-get install bcftools
```


```bash
# set to contibutor
dx-su-contrib
```

Download and filter the variants for indels; split into chunks of 5k variants


```bash
mkdir cadd_input
dx mkdir -p '/Scratch/cadd_input'
dx mkdir '/Scratch/cadd_results'
```

Test with chrY

```bash
for N in "Y"; do

dx cat "Bulk/DRAGEN WGS/DRAGEN population level WGS variants, PLINK format [500k release]/ukb24308_c${N}_b0_v1.pvar" |\
awk -F' ' 'BEGIN{print "##fileformat=VCFv4.2"}NR==1{gsub(" ","\t")}NR>1{for(c = 6; c<=NF; ++c) $c = "."}{print }' OFS='\t' |\
bcftools view -V snps --write-index -Oz -o cadd_input/chr${N}.vcf.gz &> /dev/null


bcftools +scatter "./cadd_input/chr${N}.vcf.gz" -Ob -o cadd_input/ -n5000 --prefix "chr${N}.indels."

dx upload --no-progress --brief cadd_input/chr${N}.indels.*.bcf --path "/Scratch/cadd_input/" &> dx_uploads.chr${N}.log && rm cadd_input/chr${N}.*

done
```

This is fairly fast (a few minutes). If all is ok, contiue with the remaining chromosomes


```bash
for N in {22..1} ; do
# If adding chrX as well, note that it contains PAR contigs which needs special handling (e.g., replace with X and sort before saving as vcf/bcf). 

dx cat "Bulk/DRAGEN WGS/DRAGEN population level WGS variants, PLINK format [500k release]/ukb24308_c${N}_b0_v1.pvar" |\
awk -F' ' 'BEGIN{print "##fileformat=VCFv4.2"}NR==1{gsub(" ","\t")}NR>1{for(c = 6; c<=NF; ++c) $c = "."}{print }' OFS='\t' |\
bcftools view -V snps --write-index -Oz -o cadd_input/chr${N}.vcf.gz &> /dev/null


bcftools +scatter "./cadd_input/chr${N}.vcf.gz" -Ob -o cadd_input/ -n5000 --prefix "chr${N}.indels."

dx upload --no-progress --brief cadd_input/chr${N}.indels.*.bcf --path "/Scratch/cadd_input/" &> dx_uploads.chr${N}.log && rm cadd_input/chr${N}.*

done &
```

This will take a while (possibly > 12hrs), hence running in the background. Consider exiting the terminal and connecting back later on. Make sure the time out is long enough (e.g., `dx-set-timeout 24h`), detach the session (`tmux detach`) and exit without terminating the job.


When the upload is finished, all files in the target directory will be 'closed'. Sort the files by sample size to see if any are still processing (won't show a file size). When all are done, ssh back to the job (`dx ssh <running-job-id>`) and generate batch input tables or contibue doing that locally (detailed below).


Once done, remember to terminate the VM (especially if using TTYD) either from the platform or after ssh-ing back in.

```bash
dx terminate $DX_JOB_ID
```



## Batch input


Since this does not contain genetic data, it can be done locally or on CWS/TTYD VM.

Batch input TSV contains three columns: the batch ID, the input file names (array), and input file IDs (array).

First, create a test file using chrY. Start with a header:

```bash
mkdir cadd_batch_files

echo -e "batch ID\tcadd_input\tcadd_input ID" > ./cadd_batch_files/cadd_test_batch.tsv
```

Pull the file names and IDs:

```bash
dx find data --json --class file --state closed --path "/Scratch/cadd_input" \
--name "^chrY.indels\..*\.bcf$" --name-mode regexp |\
jq -r '
    [range(0; length; 100) as $i | .[$i:$i+100]] | 
    to_entries[] | 
    "\(.key + 1)\t[" + ([.value[].describe.name] | join(",")) + "]\t[" + ([.value[].id] | join(",")) + "]"
  ' >> ./cadd_batch_files/cadd_test_batch.tsv
```

chrY will have 3 batches

```bash
wc -l ./cadd_batch_files/cadd_test_batch.tsv
```


If the applet is not already compiled, build it:

```bash
git clone https://github.com/mahmoudkoko/UKB_WGS_500k_RVAS.git
dx build -f -d 'Applets/CADD' --brief UKB_WGS_500k_RVAS/applets/cadd/
```


Run the applet with the test batch file

```bash
dx run Applets/CADD \
--batch-tsv cadd_batch_files/cadd_test_batch.tsv \
--destination "/Scratch/cadd_results/" \
--priority high \
--brief \
-y
```

This will take a while (> 2hrs). 

If all is fine, submit the remaining files.


```bash
echo -e "batch ID\tcadd_input\tcadd_input ID" > ./cadd_batch_files/cadd_batch_input.tsv

# add '|X' to regexp to get chrX as well
dx find data --json --class file --state closed --path "/Scratch/cadd_input" \
--name "^chr[1-9]|1[0-9]|2[0-2]\.indels\..*\.bcfs$" --name-mode regexp |\
jq -r '
    [range(0; length; 100) as $i | .[$i:$i+100]] | 
    to_entries[] | 
    "\(.key + 1)\t[" + ([.value[].describe.name] | join(",")) + "]\t[" + ([.value[].id] | join(",")) + "]"
  ' >> ./cadd_batch_files/cadd_batch_input.tsv
```


There are about 380 batches.
```bash
wc -l ./cadd_batch_files/cadd_batch_input.tsv
```

Sumbit all batches. The platform will limit the number of ongoing jobs but the remaining jobs will wait in the queue. Run on high priority if you can afford it (otherwise, this will take long to finish scheduling).

```bash
dx run Applets/CADD \
--batch-tsv ./cadd_batch_files/cadd_batch_input.tsv \
--destination "Scratch/cadd_results/" \
--priority high \
--brief \
-y
```


## Failed jobs

If the job has failed, it is likley that it hit mem limit. Simply reschedule with smaller numer of parallel annotation tasks or use a larger machine.

It is possible that a few files per job fail, rather than the whole job. There are log files that will list the names of failing files. Use those to create new batches and resubmit. Ideally, reduce parallel tasks and/or use a larger machine. Also consider adjusting the timeout for parallel tasks. These files will likley take longer to run and require more mem. The log files can help identifying the issue and making sensible choices.
